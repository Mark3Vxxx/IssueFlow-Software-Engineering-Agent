# IssueFlow 阶段一 MVP 设计规格

## 目标

在 Apple Silicon Mac 上，以 Docker 为受控执行环境，针对固定版本的 `karpathy/micrograd` 运行一个真实的单 Agent Issue 修复流程。用户可在 Streamlit Demo 中选择预设案例，查看从故障复现、代码检索、补丁生成、公开测试到审查结论的完整可回放轨迹。

阶段一交付的是可展示、可复现的端到端 MVP，而不是通用自动修复平台或多 Agent 对比实验。

## 范围与边界

### 包含

- 一个固定提交的 `karpathy/micrograd` 仓库副本及其可复现 Python 环境。
- 五个预设 Benchmark 样本：三个可追溯的历史修复样本，两个明确标注来源与构造方式的自建边界样本。
- DeepSeek 驱动的单 Agent，具备受限的检索、读取、编辑和测试能力。
- 默认禁网的 Docker 沙箱，限制仓库挂载范围、CPU、内存、单任务时长与工具调用次数。
- SQLite 中的结构化运行记录及对应 JSON 轨迹导出。
- Streamlit 案例工作台，展示一次真实运行的状态、证据、日志、补丁、审查和指标。

### 不包含

- 固定四角色工作流、动态 Supervisor 和四组基线实验。
- 任意外部仓库导入、自动 `git push` 或自动创建 Pull Request。
- 隐藏测试服务、分布式执行器、异步队列或 FastAPI 服务层。
- 将 LLM 审查结论作为功能正确性的唯一判据。

## 系统结构

```text
预设样本 → 任务服务 → Docker 沙箱 → 单 Agent（检索 / 编辑 / 测试）
                 │                         │
                 │                         └─ 工具事件、计划与停止原因
                 ↓
          SQLite 运行记录 + JSON 轨迹
                 ↓
          Streamlit 案例工作台
```

### Benchmark 模块

每个样本记录：唯一 ID、Issue 描述、仓库 URL、固定故障提交、许可证、样本类型（`historical` 或 `constructed`）、故障复现命令、公开验证命令、真实补丁参考（如适用）和构造说明。样本在运行前都必须验证：故障版本可以复现失败，参考修复后验证命令可以通过。

### Docker 沙箱

每次任务从固定仓库版本创建独立工作副本。容器默认没有网络，仅可访问任务工作目录与预构建依赖。宿主机 API Key 不挂载进容器；模型调用由宿主侧 Agent 适配层完成。沙箱执行命令有白名单、总时长、单命令时长、CPU、内存和输出长度上限。

### 单 Agent

Agent 使用配置化 DeepSeek 模型适配层，并接收 Issue、预算和经工具取得的上下文。它只能调用：文件搜索、文件读取、受控补丁编辑、公开测试。一次运行的最大工具调用数、最大修复轮数、最大运行时间、最大输入/输出 token 和最大估算 API 成本由任务配置设定。预算耗尽时必须停止，并在轨迹中写入失败证据和人工下一步建议。

### 轨迹与持久化

SQLite 保存任务、步骤、工具调用、指标和产物索引。每个步骤包含不可变的顺序号、时间戳、`role`（阶段一固定为 `single_agent`）、`step_type`、输入摘要、工具参数摘要、输出摘要、关联文件/行号、耗时、token、成本和结果状态。JSON 导出保留相同的稳定字段，供 Demo 展示与阶段二复现实验复用。

### 审查与成功判定

审查先运行确定性检查：公开测试是否通过、变更是否仅在工作区、是否超预算、是否产生可读 diff。满足这些前提后，模型 Reviewer 依据 Issue 和 diff 生成 `approved`、`needs_changes` 或 `failed` 结论及简要理由。MVP 的功能成功条件是：故障被复现、Agent 生成补丁、公开验证通过且未超预算；Reviewer 结论单独展示，不替代测试结果。

### Streamlit Demo

Demo 首页呈现预设案例、当前/最近运行状态、耗时、成本、工具调用数和结果。案例工作台按时间顺序呈现 Issue、Agent 计划、检索证据、工具日志、补丁 diff、测试输出、Reviewer 结论和原始轨迹下载入口。运行过程允许轮询刷新；首期不要求后台队列。

## 数据流与失败处理

1. 用户在 Demo 选择预设样本并启动运行。
2. 服务验证样本元数据与预算，创建独立 Docker 工作区和运行 ID。
3. Agent 先复现故障，再逐步检索、编辑和执行公开测试；每次操作即时追加轨迹。
4. 成功后运行 Reviewer；失败、超时、预算耗尽或工具异常时立即停止。
5. 任务状态、日志索引、diff 与指标写入 SQLite，并导出 JSON；Demo 从这些产物读取展示。

失败运行必须保留最后一次测试输出、已修改 diff、消耗的预算、停止原因和建议的人工下一步。任何日志、数据库或导出的 JSON 均不得保存 API Key。

## 验收标准

1. 在 Apple Silicon Mac 上可用单一项目命令构建并启动 Docker 受控运行环境。
2. Demo 能选择任一预设样本、触发一次真实 Agent 运行并查看结果。
3. 至少一个样本可完成“复现失败 → 生成补丁 → 公开测试通过”的演示。
4. 每次运行都可从 SQLite 和 JSON 恢复展示轨迹，且显示耗时、工具调用数、token 和估算成本。
5. API Key 仅由宿主机环境变量提供，不能进入 Git、日志、数据库、示例或截图。

## 阶段二兼容性

轨迹保留 `role` 和 `step_type`，预算接口对角色无特殊假设，因而可在不迁移历史运行数据的前提下增加 Planner、Retriever、Coder、Reviewer 与 Supervisor。阶段一不预设动态多 Agent 优于其他基线。
