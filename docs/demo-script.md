# IssueFlow 三分钟演示稿

目标：在 3 分钟内讲清楚“选题—真实修复—证据—边界”，同时让观众知道哪些是 Agent 能力，哪些是系统的确定性保障。

## 演示前准备

在同一个终端完成：

```bash
source .venv/bin/activate
export DEEPSEEK_API_KEY='你的-key'
make docker-build
make verify-benchmarks
make demo
```

浏览器打开 `http://localhost:8501`。不要在演示中显示或朗读 API Key。建议提前确认 Docker Desktop 正常运行，并预留一次 `constructed-01` 真实修复所需的 API 等待时间。

## 0:00–0:25：介绍目标

讲解词：

> IssueFlow 阶段一不是通用自动修复平台，而是一个可复现、可观察的单 Agent 实验。它把固定 Benchmark、隔离执行、真实模型修复、独立验证、Reviewer 和轨迹存储串成一条完整链路。

在页面上指出标题和案例选择器。

## 0:25–0:50：选择案例

选择 `constructed-01 · 自建边界样本`。

讲解词：

> 这个案例在固定的 micrograd 版本上人为注入一元负号回归。它是自建样本，不是上游历史 Bug。系统另外有一个历史样本，二者在来源上明确区分，所有样本都固定 commit、记录 MIT 许可证和公开来源。

## 0:50–1:10：启动真实修复

点击“开始真实修复”。

讲解词：

> 点击后会创建独立 Git 工作区，在默认断网的 Docker 中先确认故障确实存在，再让真实 DeepSeek 单 Agent 通过四种白名单工具工作：搜索、读文件、应用补丁和运行登记测试。页面每两秒检查一次进度，按钮会被锁定，避免重复并发启动。

如果 API 尚未返回，继续讲安全边界，不需要空等：

> Agent 不能访问任意 Shell、不能越过工作区，也受到时间、工具、补丁、Token 和成本预算限制。API Key 只在宿主进程中读取，不会进入修复容器或运行轨迹。

## 1:10–1:40：查看成功证据

运行完成后，指出“功能验证通过”和五个指标卡。

讲解词：

> 成功不是模型自己宣布的。系统要求故障先复现失败、产生非空 diff、独立验证通过，并且预算没有耗尽。这里还显示执行步骤耗时、工具调用、输入和输出 Token 以及估算成本。

强调“总耗时”是轨迹中已记录执行步骤之和，不是包含 API 网络等待的墙钟时间。

## 1:40–2:10：查看 diff 与测试

滚动到“代码改动”，展示 `return self` 变成 `return self * -1`。

讲解词：

> 这是相对于故障基线的真实 Git diff。时间线里可以看到 Agent 内部先运行了登记测试，随后 RunService 又在独立步骤中复验，避免只相信 Agent 的自报结果。

展开“故障复现”和“独立验证”两项：前者应为 `failed_as_expected`，后者应为 `passed`。

## 2:10–2:35：Reviewer 与轨迹

指出 Reviewer 状态和原因，再快速浏览 8 步时间线。

讲解词：

> Reviewer 是建议层。即使模型 Reviewer 不可用，只要确定性门槛通过，功能结论仍然有测试证据；反过来，Reviewer 也不能把失败测试改成成功。所有输入摘要、输出、状态和指标都按顺序写进 SQLite，并可下载为脱敏 JSON。

点击或指出“下载 JSON 轨迹”，无需在现场打开大文件。

## 2:35–3:00：局限与结论

讲解词：

> 阶段一只覆盖一个小型 Python 仓库、五个固定案例、一个 Agent、公开验证和本地 SQLite。它不修复任意仓库、不运行隐藏测试，也不会推送代码或创建 PR。当前价值是把最小真实闭环做成可复现、可审计的基础；下一阶段才能在保持边界的前提下扩展样本、重复评估和任务队列。

最后打开或口头引用 `docs/phase-1-evaluation.md`：5 个样本的参考补丁回放全部通过，真实 DeepSeek 成功记录单独列出，没有把参考答案回放混成 Agent 成绩。

## 现场异常备用话术

- **页面提示未设置 Key**：回到启动页面说明 Key 必须在启动 `make demo` 的同一终端设置，然后重启工作台；不要现场打印 Key。
- **Docker 未运行**：启动 Docker Desktop 后重新执行 `make docker-build`，说明沙箱是完整运行链路的必要组成。
- **API 等待或失败**：展示仓库内 `artifacts/phase-1/constructed-01-live-run.json` 的既有真实运行和评估报告，同时明确这是已记录证据，不冒充当前现场运行。
- **Agent 本次失败**：保留失败时间线，说明可观察失败也是系统目标之一；不要手工篡改状态，随后依据停止原因重跑。
